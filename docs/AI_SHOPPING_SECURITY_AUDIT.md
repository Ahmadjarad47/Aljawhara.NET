# AI Shopping security audit — 2026-10-23

## Scope and trust boundaries

Source review, deterministic unit/provider tests, isolated local PostgreSQL integration tests, ASP.NET TestServer HTTP boundary tests and ChromeHeadless tests of the existing Angular assistant/CartService. No destructive production testing, real customer data or paid model requests were used. Production infrastructure, pgvector runtime and live-model resistance to injection remain unverified.

Threat guidance: [OWASP LLM01 prompt injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/), [LLM06 excessive agency](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/) and [API1 object authorization](https://owasp.org/API-Security/editions/2023/en/0xa1-broken-object-level-authorization/). Model prompts are not authorization controls. Browser bodies, customer messages, catalog descriptions and model output are untrusted.

Flow: browser -> identity/limit filter -> isolated orchestrator -> restricted Responses tools -> bounded projection search -> live commerce eligibility -> decimal preview -> explicit approval -> read-only prepare-cart -> existing browser CartService. The separate optional server-cart gateway remains closed. OpenAI receives public catalog facts, structured shopping state and bounded messages, never the owner hash, capability/JWT, customer profile, addresses, payment data or order history.

## Findings and residual risks

1. **Updated — existing browser cart integrated.** Angular source was located and its real CartService now applies explicitly approved, server-prepared batches. Tests cover safe rendering, no addition before approval, legacy storage migration, duplicate concurrent approvals/reload/clear, changed stock, blocked persistence and identity changes. Preparation returns only `prepared`; actual success is reported after a cart storage commit. Checkout still authoritatively validates prices, stock and promotions. The unused future server-cart gateway remains closed. Verify this browser integration against staging before release.
2. **Release blocker — real-data quality and live AI evaluation.** Package/material schema is untyped. Only explicitly labelled, unambiguous integer packaging is accepted. Unknown physical pack sizes are unavailable; variants are excluded because checkout cannot represent them. Catalog coverage and customer usefulness must be measured on production-like data. Fixture evaluation is not live Arabic model accuracy.
3. **Deployment verification — pgvector runtime.** The local host lacked vector and its C++ toolchain headers. The optional test is skipped locally unless ECOM_TEST_VECTOR=1; the added CI job provisions pgvector and must pass before semantics is enabled. Exact scans and RRF code build, lexical fallback was executed; production semantic performance is not claimed.
4. **Prompt injection can still bias needs or candidate selection.** It cannot gain write tools or set authoritative prices through this interface. Human review is required, and model relevance must be evaluated separately. No prompt can guarantee total resistance.
5. **Operational limits.** Rate/concurrency state is per API process. Upstream aggregate controls are required for multiple replicas. Guest capabilities require protected, persistent/shared Data Protection keys. A valid stolen token grants its guest scope until expiry; do not log/store it in unsafe locations.
6. **Replay and concurrency scope.** Browser cart contents/operation receipts share one localStorage commit, and Web Locks serialize AI additions across tabs. Site-storage deletion or writes by older cached application versions can remove those receipts. Normal manual cart actions preserve their existing synchronous semantics and are not a distributed transaction. This client state grants no order/payment authority. The optional future server gateway still requires its own atomic operation receipt for its separate crash window.
7. **Eventual search projection.** Full bounded sweeps discover description/detail/category changes without modifying business tables. Catalog deletion/eligibility/stock/price are rechecked live, but semantic/lexical content can lag until a sweep. Exact vector scans require production-size p95 measurement; no approximate-index claim is made.
8. **Pre-existing issues, outside this change:** production DataSeeder currently resolves commerce DB/Identity and seeds demo entities; its baseline production-seeding test fails. Existing deploy workflow publishes master without running tests. Initial build has 12 nullable warnings. Backup/browser test setup has environment prerequisites. These are reported rather than hidden or rewritten as unrelated feature work.

The feature remains disabled by default. No production deployment, secret modification, order creation, refund or payment action was performed.
