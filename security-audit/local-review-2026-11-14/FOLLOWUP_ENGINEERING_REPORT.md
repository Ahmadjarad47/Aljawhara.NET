# Aljawhara local engineering follow-up

**Local verification covered password recovery, transaction retention, account quota isolation and two shipping address defects.** Public search issues two fewer SQL commands for the measured request. This remains a partial defensive assessment. No deployment or production access occurred. Existing working-tree edits were preserved.

## Failure recovery and test results

- The new checkout test discards a successful response body and retries against a second host. It asserts one committed order, one financial transaction, one reservation and a single stock decrement.
- The new migration test forces a PostgreSQL index-name collision after the catalog migration starts. It verifies rollback of both new columns and migration history, preservation of the old row, then a successful retry after removal of the fixture fault. Both new tests passed on a fresh loopback PostgreSQL cluster.
- The [live database snapshot](followup-database-invariants.json) found zero orphaned transactions, zero orphaned order items and zero negative stock rows. All four synthetic ledger records and the one submitted visitor record remained present.
- The checkout suite exercised rollback after an identity write, inventory contention, payment confirmation races, product/image deletion relationships, expired worker lease recovery, and real PostgreSQL dump and restore with backup retention after failure. These are bounded fixtures; a network disconnect at the precise commit boundary and process termination with a provider request in flight were not simulated.
- The isolated solution run after the address index migration passed **393 tests**, with two skips for paid provider and pgvector. After the history fix, the four targeted regressions and the full **311-test checkout suite** passed. The three AI suites passed 83 tests in the solution run. These builds used versions available in the local NuGet cache. The workspace's newer dependency set still cannot be restored offline. [Backend test runs](followup-backend-tests.json)
- All **237 Angular specs passed** after correcting the test copy to use an absolute loopback API URL. The earlier 14 failures came from the relative URL configured for the audit. The local SSR build passed and prerendered 30 static routes. The home page, product listing and product detail rendered fixture data and returned `Cache-Control: no-store`. Both recovery pages returned 200. The SSR build used 659.37 kB of initial browser assets and 145.56 kB estimated transfer. External font and critical CSS inlining were disabled in the copied build. [Angular tests](followup-angular-tests.json) and [live SSR evidence](followup-angular-ssr.json)
- The main [browser run](followup-browser.json) passed 13 storefront/admin checks. Its first combined recovery attempt requested a new code within the existing cooldown. The separate [recovery regression](followup-recovery-result.json) accounted for the cooldown and passed on the fresh build.

## Performance

The same 1,001-product fixture and two local builds were compared. See [warm comparison](followup-performance.json), [fresh-process comparison](followup-performance-repeat.json), and the [representative title-filter plan](followup-search-plan.txt).

| Request | Body bytes | SQL before → after | p50/p95 before → after (ms) |
| --- | ---: | --- | --- |
| Full catalog, first request after process start | 294,104 | 1 → 1 | 304.62 → 274.67 (one observation per process; no percentile claim) |
| Full catalog, warm, 12 per build | 294,104 | 0 → 0 | 4.36 / 16.51 → 4.29 / 16.56 |
| Filtered page, uncached, 12 per build | 6,264 | 3 → 3 | 5.54 / 7.32 → 5.61 / 6.58 |
| Public search, uncached, 28 per build, run 1 | 312,790 | 4 → 2 | 21.77 / 31.71 → 30.71 / 44.97 |
| Public search, uncached, 28 per build, run 2 | 312,790 | 4 → 2 | 49.84 / 78.53 → 33.62 / 45.91 |

The reduction in SQL work was consistent. The unfiltered catalog and broad search still return large arrays. The paged response used about one forty-seventh of the full catalog's bytes. The representative title filter ran a sequential scan over the small fixture and took 0.354 ms. Process CPU and memory samples include workers and have different starting states, so they cannot establish a regression or improvement. One authenticated request issued a session query. The database snapshot showed four idle connections and one active inspection connection. Pool saturation and per-request allocation remain unmeasured. Angular customer navigation made nine shipping reads and eight category reads across multiple pages. Same-render duplicates and render cost remain unmeasured. [Authenticated request and pool snapshot](followup-auth-db.json)

A two-connection PostgreSQL fixture held an uncommitted stock update. A second write timed out with a 250 ms lock budget and 339.1 ms measured end to end, including local client startup. Reads still saw the committed stock. The second connection could write after release and the final stock matched its original value after both rollbacks. Checkout and payment tests separately covered contention and business invariants. [Lock evidence](followup-lock-contention.json)
